# Multi-Tenant SaaS Migration Plan

**Goal:** Transform existing single-tenant School Management System into a production-ready multi-tenant SaaS platform.

**Stack:** Next.js 15.1.3, TypeScript, Prisma 6.1.0, PostgreSQL, NextAuth v5 beta, Tailwind, Radix UI, Recharts

**Approach:** 10 incremental phases, each independently deployable. No rewrite — extend and refactor.

---

## Architecture Summary

**Tenancy Model:** Shared database, shared schema, discriminator column (`schoolId`).

```
Middleware → JWT carries { id, email, role, schoolId }
            → Tenant resolution from subdomain or session
          ↓
Prisma    → Client Extensions auto-append WHERE schoolId = ?
            → AsyncLocalStorage carries tenant context per request
          ↓
PostgreSQL → Shared DB, schoolId on every business table
```

**Role Hierarchy:**
```
SUPER_ADMIN (100)  → Platform management, all schools
SCHOOL_ADMIN (80)  → Full access within their school
ACCOUNTANT (60)    → Finance, invoices, payments
TEACHER (40)       → Students, attendance, exams, homework
STAFF (40)         → Similar to teacher
PARENT (20)        → Portal view of their children
STUDENT (10)       → Read-only: timetable, homework, results
```

**Dashboard URLs:**
```
/super-admin/          → Super Admin panel
/dashboard/            → School Admin (preserves current URL)
/portal/parent         → Parent portal
/portal/student        → Student portal
```

## Phase 2: Tenant-Aware Data Layer

**Goal:** Every Prisma query automatically scopes to current tenant.

### Approach: Two-Layer Tenant Scoping

**Layer 1 — Prisma Client Extensions (auto-pilot):**

Extend the singleton in `src/lib/prisma.ts` with `$extends` that:
- Auto-appends `WHERE schoolId = ?` on findMany/findFirst/count/groupBy
- Auto-sets `schoolId` on create/createMany
- Only activates for models in a TENANT_MODELS list
- Reads tenant ID from AsyncLocalStorage

**Layer 2 — Explicit `tenantWhere()` (safety net):**

Utility function in `src/lib/tenant.ts` for complex queries that need manual control.

### API Route Migration Pattern

Every API route (64+) gets updated:
```typescript
// BEFORE: prisma.student.findMany({ where: { status: "ACTIVE" } })
// AFTER:  prisma.student.findMany({ where: tenantWhere({ status: "ACTIVE" }) })
```

Wrap route handlers with tenant context:
```typescript
import { withTenantContext } from "@/lib/api-helpers";
export const GET = withTenantContext(async (req) => { ... });
```

### Data Migration Script

`prisma/seed-tenant.ts`:
1. Create default Organization from existing Setting
2. Set schoolId on ALL existing rows to default org
3. Link Setting to org
4. Create default FREE subscription
5. Verify no orphaned rows

### Files to Create/Modify

| File | Purpose |
|------|---------|
| `src/lib/prisma.ts` | Add Client Extensions for auto tenant scoping |
| `src/lib/tenant.ts` | tenantWhere(), withTenant() utilities |
| `src/lib/tenant-context.ts` | AsyncLocalStorage context |
| `src/lib/api-helpers.ts` | withTenantContext() route wrapper |
| `prisma/seed-tenant.ts` | Data migration script |

## Phase 9: Polish, Security Audit & Launch

**Goal:** Security hardening, performance, testing.

### Security Checklist
- Every API route has tenantWhere() or requireTenantAuth()
- No cross-tenant data leakage possible
- JWT cannot be forged
- CSRF protection on all state-changing routes
- Rate limiting per tenant
- Audit logging on sensitive operations
- Super admin routes fully isolated
- File upload storage tenant-isolated

### Performance
- Composite indexes for (schoolId, ...) on frequently queried columns
- Connection pooling consideration for multi-tenant workload
- Lazy load dashboard components per role

### Testing
- Tenant isolation tests (verify School A cannot see School B data)
- RBAC tests (verify each role's permissions)
- API tests for role-based access
- E2E tests for login flow

## Data Migration Strategy

1. **Phase 0:** Add `schoolId` as nullable (`String?`). App continues working.
2. **Run `prisma/seed-tenant.ts`:** Creates default org, assigns all existing data.
3. **Phase 2:** App code starts using `tenantWhere()`. Existing data has `schoolId = defaultOrgId`.
4. **Phase 1:** New users get `schoolId` from JWT. Existing users re-login.
5. **After all phases:** Make `schoolId` required (non-nullable) via final migration.
